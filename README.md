# Speakly - застосунок для вивчення іноземних мов

**Speakly** - навчальний кросплатформний застосунок для вивчення іноземних мов. Користувач додає слова з перекладом до власного словника, переглядає їх, шукає, сортує та видаляє, а дані зберігаються між запусками.

Головна особливість проєкту - **одна спільна бізнес-логіка для веб- та десктопного клієнтів**: пакет `@speakly/core` підключається до обох клієнтів через платформні адаптери збереження.

### Історія проєкту

| Пункт | Опис |
|---|---|
| **Назва проєкту** | Speakly - кросплатформний застосунок для вивчення іноземних мов |
| **Проблема** | Розробка мобільного, декстопного та веб-застосунку для вивчення іноземних мов, вирішує проблему відсутності часу або фінансів під час вивчення іноземних мов, бо застосунок гручкий і адаптивний, ти можеш займатися будь-де і будь-коли, як саме тобі зручніше |
| **Моя роль і внесок** | Я самостійно розробила всі частини проєкту: REST і GraphQL API, веб-клієнт на React, мобільний застосунок на React Native, десктопний застосунок на Electron. У монорепозиторії виділила спільне ядро `@speakly/core`, реалізувала `WordsService`, платформні адаптери та автоматичні тести. |
| **Обраний стек технологій** | **Платформи:** веб, мобільна та десктопна версії охоплюють основні середовища користувача. **Клієнти:** React зручний для компонентних інтерфейсів, React Native дозволяє використати ті самі знання для мобільної версії, Electron перетворює вебтехнології на десктопний застосунок. **Спільний код:** npm workspaces дають змогу тримати ядро й клієнти в одному репозиторії без публікації пакетів. **API:** Express показує класичний REST, Apollo Server із JWT демонструє GraphQL та захищені запити. **Дані:** MongoDB підходить для слів як гнучких документів, а `localStorage` і JSON-файл достатні для локального зберігання в клієнтах. |
| **Найскладніший кросплатформний виклик і рішення** | Найскладніше було зробити спільну логіку для клієнтів, які зберігають дані по-різному: браузер працює з `localStorage`, а Electron із файлом на диску. Рішення - патерн «спільне ядро + платформні адаптери»: ядро залежить лише від інтерфейсу `load()` / `save()`, а кожна платформа реалізує власний адаптер. Завдяки цьому перевірка, додавання, пошук і видалення слів працюють однаково в обох клієнтах. |
| **Здобуті знання та вміння** | Див. підсумок нижче. |

### Що я знаю та чому навчилася

- створювати односторінкові вебзастосунки на **React** із Hooks (`useState`, `useEffect`), **Vite** і **Tailwind CSS**;
- будувати мобільні застосунки на **React Native** та запускати їх через **Expo Go**;
- створювати десктопні застосунки на **Electron**: головний процес, preload, **IPC**, безпечна ізоляція контексту;
- розробляти **REST API** на Node.js та Express 5 і **GraphQL API** на Apollo Server з автентифікацією через **JWT**;
- працювати з **MongoDB Atlas** і **Mongoose**, а також із локальними сховищами (`localStorage`, JSON-файл);
- організовувати **монорепозиторій** за допомогою npm workspaces;
- проєктувати спільне ядро та платформні адаптери, застосовувати Dependency Injection;
- писати автоматичні тести на `node:test`.

## Структура репозиторію

Репозиторій містить усі лабораторні роботи з дисципліни. 

```text
WEB-Shevchenko-cross-platform-programming/
├── cross-platform-lab-1/     # ЛР №1: налаштування середовища, порівняльний аналіз підходів
├── speakly-server/           # ЛР №2: REST API (Node.js, Express, MongoDB)
├── graphql-auth-lab3/        # ЛР №3: GraphQL API (Apollo Server, JWT)
├── speakly-lessons/          # ЛР №4: веб-версія SPA (React, Vite, Tailwind CSS)
├── vocab-words/              # ЛР №5: мобільний застосунок (React Native, Expo)
├── speakly-desktop/          # ЛР №6: десктопний застосунок (Electron)
└── speakly-monorepo/         # ЛР №7-8: монорепозиторій зі спільним ядром
    ├── packages/
    │   ├── core/             # Спільна бізнес-логіка (@speakly/core)
    │   ├── web/              # Веб-клієнт (localStorage)
    │   └── desktop/          # Десктопний клієнт Electron (words.json, IPC)
    ├── package.json
    └── README.md             # Цей файл
```

| Лабораторна | Тека | Що реалізовано |

| №7-8 | [`packages/core`](packages/core), [`packages/web`](packages/web), [`packages/desktop`](packages/desktop) | Спільне ядро та два клієнти |
